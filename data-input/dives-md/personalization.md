# Personalization: How User History Shapes Your Search Results

## Key Insight
Google's public position on personalization contradicts its internal reality. Benedict Gomes (UPX1044, 2018): 'Personalization only rarely happens as part of the ranking process... everyone sees generally the same results.' But the Priors algorithm (UPX0205, 2015) is described as 'one of the strongest signals for much of Google's search and ads ranking' and works by matching users based on 'behavioral similarity' from past actions. Judge Mehta (FOF #121-125) found Google tracks user sessions, logs IP addresses for result customization, retains 18 months of user data, and invites sign-in because 'personalization improves search quality.' The logged-in latency penalty (350ms, UPX2022) proves personalization infrastructure is real and resource-intensive.

### Signals, Core (doj)
- Priors algorithm (UPX0205, Research All-Hands Apr 2015): 'Score the doors based on how many people took it. Rank the choices based on how popular it is.' 'One of the strongest signals for much of Google's search and ads ranking.' Behavioral similarity: 'describe results by the people who chose them.' 'We don't use demographics or stereotypical attributes. We simply use a user's past actions to describe them and match users based on their behavioral similarity'
- Personalization listed as one of 18 Search Quality Aspects (doj:18-search-quality-aspects). Evaluated by human raters alongside relevance, page quality, popularity, freshness, localization, language, spam detection, and authority
- Session tracking (Mehta FOF #121): 'Whether to track a user's sessions data is one such decision. According to Google, tracking user sessions is measurably beneficial to the user experience, including things like in-session use of context to improve results.' Data also 'helps to tailor the advertisements that Google delivers to a user'
- IP address logging (Mehta FOF #122): 'Google logs IP addresses and uses them to customize search results.' Lehman: 'Knowing a person's location can sometimes help understand what it is they're looking for'
- Sign-in functionality (Mehta FOF #124): Google invites sign-in because it 'believes such functionality improves search results and overall search engine quality.' Ramaswamy testimony: 'personalization improves search quality'
- 18-month data retention (Mehta FOF #125): Google retains 18 months of user data despite surveys showing 49% of users preferred 1 month or less, and 74% wanted under 1 year. Decision 'largely arbitrary' per Fitzpatrick testimony
- Benedict Gomes reintroduction (UPX1044, Nov 2018): 'Personalized results are customized based on information unique to an individual, such as their search history.' Personalization includes: ranking (how results are ordered), understanding (using search history to understand queries), recollection (predictions of past searches). But claims it 'rarely happens' and is not needed for most queries
- Logged-in latency penalty (UPX2022, DX0099): 'Results for logged-in user queries on Google arrive ~350ms later than queries by logged-out users.' Google has a 'significant logged-in penalty' from personalization infrastructure. Bing: only ~100ms slower for logged-in
- Click data learning (UPX0219, Lehman): 'Learning from logs is the main mechanism behind ranking.' All major ML systems rely on logs: RankBrain, RankEmbed, DeepRank. 'With every query, we give some knowledge, and get a little back. After a few hundred billion rounds, we start lookin' pretty smart'

### Personalization Infrastructure (leak)
- GWS personalization overlay: GWS applies personalization overlays based on user history, preferences, and session data as the final delivery step. Logged-in users may see personalized result ordering
- NavBoostLocationSlice - Click data segmented by geographic location. Location-based personalization through regional click patterns
- NavBoostDeviceSlice - Click data segmented by device type (mobile/desktop). Device-based result differentiation
- sliceTag - Flexible segmentation key in CRAPS allowing ad-hoc signal slicing by device, country, locale, or custom dimensions. Enables personalization-like segmentation
- voterTokenCount - Tracks distinct voter tokens as lower bound on distinct users. Indicates Google tracks user identity across sessions for anti-manipulation and personalization
- QSessions - Structured internal session model tracking query, clicks, reformulations, and session termination. Primary data source for in-session personalization

### 7 Patents (patent)
- Phrase-based personalization (US7426507): Phrase-based personalization of searches in an information retrieval system
- User-context-based search (US9449105): Search personalization using user context signals
- Privacy-preserving personalized LLMs (US20240403564): Modern approach to personalization via privacy-preserving personalized language models
- Personalized information filtering (US6381594): System and method for personalized information filtering and alert generation
- Content personalization via browsing session: Patent for personalizing content based on actions during current browsing session
- Demoting personalized results: Patent for systems and methods for demoting personalized search results based on personal information (anti-filter-bubble mechanism)
- Self-learning personalization: Self-learning and self-personalizing knowledge search engine that delivers holistic results

### How Personalization Affects Rankings (exploit)
- Priors algorithm = behavioral targeting: Google matches new users to existing behavioral profiles. If users who previously chose your competitors' pages have similar behavioral patterns to a new searcher, your competitor gets boosted. Building a loyal user base with recognizable behavioral patterns strengthens your position in the Priors algorithm
- Logged-in users see different results: The 350ms latency penalty proves Google runs additional processing for logged-in users. Ranking reports from logged-in accounts may not reflect what anonymous users see. Always verify rankings in incognito mode
- In-session context rewrites queries: Gomes (UPX1044): searching 'travel' then 'Spain' may refine the second search to include travel-related Spain results. Multi-page content journeys benefit from session-based context. Internal linking that guides users through related queries can amplify in-session personalization
- Location personalization is always active: IP-based location customization (Mehta FOF #122) applies to all users, not just logged-in ones. Local signals affect all searches, even 'non-local' queries. Geographic relevance is always a factor
- 18-month data window shapes rankings: Google retains 18 months of user behavior data. If users consistently prefer your competitors over 18 months, the Priors algorithm learns that pattern. Sustained user preference acquisition (not just ranking) is critical
- Video provider elevation example: Gomes (UPX1044): 'We might slightly elevate a video provider you often use to watch movies.' This confirms user habit data directly influences result ordering. Brand loyalty creates self-reinforcing ranking advantages

### Calculations
- Priors Algorithm (Behavioral Similarity): Describes users based on their past actions and matches them to results based on behavioral similarity. At Google's scale, 'even the most obscure choice would have been exercised by thousands of people.' No demographics or profiles used. Pure action-based behavioral matching. Described as 'one of the strongest signals for much of Google's search and ads ranking.' Affects: Affected by: user's past actions, behavioral patterns of result choosers, action similarity matching. Sustained user preference creates self-reinforcing advantage.
- In-Session Context Personalization: Uses the sequence of queries within a session to refine subsequent searches. Gomes example: searching 'travel' then 'Spain' refines the second query to include travel-related Spain content. QSessions tracks query, clicks, reformulations, and session termination. Autocomplete also personalizes based on session history. Affects: Affected by: query sequence within session, click patterns, reformulation signals. Multi-query journeys benefit content with clear topical progression.
- GWS Personalization Overlay: GWS applies personalization overlays as the final delivery step. For logged-in users, this adds ~350ms latency (UPX2022, DX0099). The overlay considers user history, preferences, A/B experiment assignment, geographic routing, and device adaptation. Logged-in users may see personalized result ordering. Anonymous users still receive IP-based location customization. Affects: Affected by: login status, user history, IP location, device type, A/B experiment assignment.

### Personalization in the Search Pipeline
- Query-Time Context: User's location (IP), device, language, login status, and session history collected at query time. In-session context from previous queries and clicks available.
- QUS Personalized Processing: Query understanding may use search history to disambiguate queries (Gomes: 'travel' then 'Spain'). Autocomplete predictions personalized based on session and history.
- Location-Based Retrieval: NavBoostLocationSlice applies geographic click data. Results biased toward content preferred by users in the same region. IP-based, applies to all users.
- Priors Algorithm Application: For logged-in users, behavioral similarity matching boosts results chosen by users with similar past actions. 'One of the strongest signals for much of Google's search and ads ranking.'
- Core Ranking (Ascorer): Standard T*/Q*/P* ranking runs. Most of the ranking is query-based, not user-based. Personalization adjustments are secondary to core relevance.
- GWS Delivery Overlay: Final personalization overlays applied by GWS: user history, preferences, experiment variant, device adaptation. Adds ~350ms for logged-in users.

### Timeline
- 2005 (event): Google Personalized Search Launched - Google introduces personalized search results based on search history for logged-in users.
- 2009 (event): Personalization Extended to All Users - Personalization based on recent search activity applied to all users, not just logged-in ones. Uses cookies and session data.
- 2015 (doj): Priors Algorithm Presented - UPX0205 (Research All-Hands): Priors algorithm described as 'one of the strongest signals for much of Google's search and ads ranking.' Behavioral similarity matching without demographics.
- 2017 (doj): Logged-In Latency Documented - DX0099 (SRP Latency Update): Google identifies 'logged-in penalty' of ~350ms as technical problem. Personalization infrastructure adds measurable latency cost.
- 2018 (doj): Gomes Personalization Memo - UPX1044: Benedict Gomes writes 'reintroduction to how Google uses personalization in search.' Claims it 'rarely happens' and 'everyone sees generally the same results' despite Priors algorithm being 'one of strongest signals.'
- 2023 (doj): DOJ Trial: 18-Month Data Retention - Mehta FOF #125: Google retains 18 months of user data for personalization. 74% of surveyed users wanted under 1 year retention. Decision 'largely arbitrary.'
- 2024 (patent): Privacy-Preserving Personalized LLMs - US20240403564: Patent for privacy-preserving personalized language models. Indicates Google is building LLM-based personalization for future search.

### Contradictions
- Public (Benedict Gomes, Google VP (UPX1044, Nov 2018)): Personalization only rarely happens as part of the ranking process. Why rarely? Because it is usually not needed nor helpful. Everyone sees generally the same results. vs Internal (DOJ: UPX0205 (Research All-Hands, Apr 2015) + Mehta FOF #121-125): The Priors algorithm is described as 'one of the strongest signals for much of Google's search and ads ranking.' Google retains 18 months of user data, logs IP addresses to customize results, tracks user sessions as 'measurably beneficial,' and sign-in exists because 'personalization improves search quality.' The 350ms logged-in penalty proves substantial personalization processing occurs.
- Public (Google (UPX1044)): We do not personalize results based on any type of demographic profile, nor do we create such profiles for use in Google Search. vs Internal (DOJ: UPX0205 (Priors algorithm) + UPX0219 (Lehman logging)): While Google avoids demographic profiling, the Priors algorithm creates behavioral profiles: 'describe users based on their past actions and match users based on their behavioral similarity.' All major ML ranking systems (RankBrain, RankEmbed, DeepRank) learn from logged user behavior. 'Learning from logs is the main mechanism behind ranking.' The distinction between 'demographic profiling' and 'behavioral profiling from 18 months of action data' is semantic.
- Public (Pandu Nayak (DOJ Trial testimony, PXR0357)): Personalization in Google Search is 'quite limited.' The query itself is by far the most powerful signal. vs Internal (DOJ: UPX0205 (Priors) + UPX2022/DX0099 (latency) + Mehta FOF #122 (IP logging)): The Priors algorithm is 'one of the strongest signals.' Logged-in users face 350ms additional latency from personalization processing (Bing: only 100ms). Google logs IP addresses and 'uses them to customize search results' (Mehta FOF #122). If personalization were truly limited, it would not add 350ms of server-side processing or warrant 18 months of data retention.
- Public (Google (public statements on user data)): We collect data to improve our services. User data retention is necessary for service quality. vs Internal (DOJ: Mehta FOF #125 (18-month retention)): Google retains 18 months of user data despite surveys showing 49% of users preferred 1 month or less, and 74% wanted under 1 year. Decision was 'largely arbitrary' per Fitzpatrick testimony. Google chose a retention period that exceeded user preferences because longer retention benefits ranking quality and ad targeting, not user preference.

### Overview
Google publicly claims personalization 'rarely happens' and 'everyone sees generally the same results.' Internally, the DOJ trial revealed Google retains 18 months of user data, logs IP addresses to customize results, applies personalization overlays via GWS, and uses the Priors algorithm (described as 'one of the strongest signals for much of Google's search and ads ranking'). The 350ms latency penalty for logged-in users (UPX2022) demonstrates the computational cost of personalization infrastructure. Judge Mehta found that session tracking is 'measurably beneficial to the user experience.'
