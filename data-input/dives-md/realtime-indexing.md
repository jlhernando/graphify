# Real-Time Indexing: How Google Indexes Content in Minutes, Not Days

## Key Insight
Google's real-time indexing is not just about crawling faster. The API leak reveals a dual pipeline: Trawler's three-tier crawl scheduler (Patent US7725452) determines how quickly content is fetched, while CRAPS signals (crapsNewUrlSignals, crapsAbsoluteHostSignals) determine how quickly it influences rankings. The RealTimeBoost twiddler bridges both pipelines, re-ranking results using incoming Chrome visits before the traditional NavBoost table is updated. For high-engagement URLs, the gap between publishing and ranking impact can be as short as 10 minutes via InstantGlue.

### API Leak Signals (leak)
- RealTimeBoost - Re-ranking twiddler incorporating real-time signals including incoming Chrome visits. Applied as a post-retrieval boost for content receiving sudden engagement spikes before the full NavBoost pipeline processes the data
- crapsNewUrlSignals - Chrome Realtime Aggregated Page Signals for new/fresh URLs. Provides immediate engagement metrics for recently discovered pages that lack historical NavBoost data, solving the cold-start problem for fresh content
- crapsAbsoluteHostSignals - Chrome Realtime Aggregated Page Signals at the host level. Aggregates Chrome browsing behavior across an entire domain, providing real-time site-level quality signals that can influence all pages on that host
- crapsNewNsrSignal - Site-level NSR (Normalized Site Rank) recomputed using CRAPS data in near-real-time. Allows site quality scores to update rapidly when Chrome engagement patterns shift, rather than waiting for the next batch NSR computation

### 4 Patents (patent)
- Patent US20060294086: Realtime Indexing in Rapidly Changing Document Collections - Foundational patent for real-time indexing. Describes maintaining a real-time index partition that is continuously updated as documents change, merged periodically with the main index. Enables sub-second indexing latency for the highest-priority content tier
- Patent US7634466: Realtime Indexing - Near-real-time indexing system for rapidly changing content. Implements incremental index updates without requiring full index rebuilds. The real-time partition handles insertions, deletions, and modifications as a streaming operation
- Patent US7725452: Scheduler for Search Engine Crawler - Three-tier crawl architecture: Base (200M+ URLs, comprehensive coverage), Daily (50M+ URLs, frequent changers), Real-time (5M+ URLs, breaking/critical content). Priority scoring combines PageRank, change frequency, and content importance to route URLs into the appropriate tier
- Patent US8458163: Website Owner Crawl Rate Management - Allows site owners to request faster or slower crawl rates via Search Console. Speed-up requests are only honored when the current rate limit is the binding constraint: |currentLimit - maxActualRate| < threshold. If the crawler is already below server capacity, a speed-up request has no effect

### Real-Time Indexing Implications (exploit)
- Chrome traffic is a real-time ranking input, not just a passive signal: CRAPS signals (crapsNewUrlSignals, crapsAbsoluteHostSignals) mean Chrome browsing data feeds ranking in near-real-time. If your content receives a surge of Chrome visits (from social media, email newsletters, direct shares), RealTimeBoost can amplify your ranking before the regular NavBoost cycle processes the data. This creates a flywheel: early traffic generates real-time signals that boost rankings, driving more traffic
- New URLs have a dedicated real-time signal path: crapsNewUrlSignals specifically addresses fresh URLs, solving the cold-start problem. When you publish new content and it receives immediate Chrome engagement, the system does not wait for historical NavBoost data to accumulate. This means early promotion of new content (via email lists, social channels, push notifications) directly feeds the real-time ranking pipeline
- Site-level CRAPS signals affect all your pages: crapsAbsoluteHostSignals operates at the domain level. If your site as a whole receives strong Chrome engagement, all pages benefit from the real-time host-level signal. Conversely, a sudden drop in site-wide Chrome engagement (site outage, bad press, migration issues) can depress rankings across all pages in near-real-time
- The three-tier crawl determines your content's indexing speed ceiling: Only ~5M URLs qualify for real-time crawl. To reach this tier, content needs high PageRank, demonstrated change frequency, and content importance signals. Most sites operate in the Daily (50M+) or Base (200M+) tiers. Improving server response time, internal linking to new content, and maintaining consistent update cadence are prerequisites for faster crawl tier assignment
- Search Console crawl rate requests have strict conditions: Patent US8458163 reveals that speed-up requests only work when the current crawl rate limit is actually the bottleneck. If your server is slow or content quality is low, requesting faster crawling has zero effect. Fix server performance first, then request rate increases
- NSR recomputation via CRAPS means site reputation can shift rapidly: crapsNewNsrSignal recalculates your site's Normalized Site Rank using real-time Chrome data. A viral positive event (featured in major media, trending product launch) can improve your NSR within hours rather than waiting for the next batch computation. The reverse is also true: a brand crisis visible in Chrome traffic patterns can depress NSR quickly

### Calculations
- Real-Time Crawl Tier Assignment: The crawler scheduler assigns each URL to one of three crawl tiers based on a composite priority score. The score combines PageRank (link-based importance), content change frequency (detected by comparing checksums across successive crawls), and content importance (predicted query utility). URLs in the Real-time tier (top ~5M) are fetched within minutes of a change being detected or signaled. Daily-tier URLs (~50M) are recrawled every 24 hours. Base-tier URLs (~200M+) follow a longer cycle based on their individual priority scores. Affects: Affected by: PageRank, content change rate, predicted query utility, server response speed, sitemap signals
- RealTimeBoost Signal Computation: RealTimeBoost operates as a post-retrieval re-ranking twiddler that incorporates real-time Chrome visit data. When a URL receives a sudden spike in Chrome visits (detected via CRAPS aggregation), RealTimeBoost applies a positive re-ranking signal before the standard NavBoost table is updated. The signal combines crapsNewUrlSignals (URL-level Chrome engagement for fresh URLs) with crapsAbsoluteHostSignals (host-level Chrome engagement). For new URLs without NavBoost history, crapsNewUrlSignals provides the primary engagement signal, solving the cold-start problem. Affects: Affected by: Chrome visit volume and velocity, CRAPS signal freshness, host-level engagement patterns, NavBoost data availability
- Real-Time NSR Recomputation: Normalized Site Rank (NSR) is normally computed in batch cycles, but crapsNewNsrSignal enables near-real-time recomputation using Chrome browsing data. When aggregate Chrome engagement patterns for a host shift significantly (viral event, site outage, brand crisis), the NSR is recomputed without waiting for the next batch cycle. This updated NSR then influences all ranking decisions for pages on that host, including index tier placement and crawl priority. Affects: Affected by: aggregate Chrome browsing patterns at host level, engagement velocity changes, site-wide traffic trends

### Real-Time Indexing Pipeline
- Change Detection: URL change detected via sitemap ping, RSS feed, Google Alerts, or checksum difference on recrawl
- Crawl Tier Routing: Scheduler assigns URL to Real-time (5M+), Daily (50M+), or Base (200M+) tier based on priority score
- Real-Time Fetch: Trawler fetches Real-time tier URLs within minutes. Content rendered and parsed for indexing
- Real-Time Index Partition: New/updated content enters the real-time index partition (Patent US20060294086). Merged periodically with main index
- CRAPS Signal Aggregation: Chrome Realtime Aggregated Page Signals computed: crapsNewUrlSignals (URL-level), crapsAbsoluteHostSignals (host-level)
- RealTimeBoost Application: Post-retrieval twiddler applies real-time Chrome engagement data to re-rank results before NavBoost table update
- InstantGlue Delivery: User engagement signals delivered with ~10-minute latency on 24h windows. Feeds isHotdoc flag for trending content

- Public (Google Public Statements): We don't use Chrome data for ranking. ### Overview
Google maintains a three-tier crawl architecture (Base 200M+, Daily 50M+, Real-time 5M+) that enables near-instant indexing for high-priority URLs. Chrome browser signals feed directly into ranking through CRAPS (Chrome Realtime Aggregated Page Signals), while InstantGlue delivers user engagement data with ~10-minute latency. The API leak revealed RealTimeBoost, a re-ranking twiddler that incorporates live Chrome visit data, and a family of CRAPS signals that recompute site quality (NSR) and URL-level freshness in real time.
